# 📊 Marketplace Analytics

**Задача:** понять, как возвраты влияют на выручку, и измерить, какая доля покупателей возвращается за новым заказом.

Вход — 1 296 синтетических заказов Ozon и Wildberries за январь–июнь 2025 года. Генератор фиксирует seed. Две SQL-витрины строятся из одной таблицы заказов.

| Витрина | Что считает | SQL |
|---|---|---|
| Продажи по каналам | Заказы, выручку после возвратов, долю возвратов, изменение к прошлому месяцу | [metrics.sql](metrics.sql) |
| Удержание | Размер когорты, активных покупателей и долю вернувшихся | [cohorts.sql](cohorts.sql) |

## Что получилось

| Wildberries | Апрель | Май | Июнь |
|---|---:|---:|---:|
| Заказы | 112 | 120 | 128 |
| Доля возвратов | 8,0% | 21,7% | 25,8% |
| Выручка после возвратов | 289 540 ₽ | 260 796 ₽ | 268 347 ₽ |

С апреля по май заказов стало на 7,1% больше, а выручка после возвратов снизилась на 9,9%. Из 81 покупателя январской когорты в феврале снова сделали заказ 57 человек (70,4%). Оба результата описывают сценарий генератора. Выручка здесь — стоимость невозвращённых заказов, до расходов и комиссий.

## Как устроен расчёт

- `LAG` сравнивает выручку с предыдущим месяцем того же канала.
- Когорта определяется месяцем первого заказа. Для удержания по каждому месяцу покупатель учитывается один раз, даже если сделал несколько заказов.
- [Python-скрипт](analyze.py) сверяет SQL-выручку с агрегацией в pandas и проверяет границы показателей удержания.

## Запуск

```bash
python -m pip install -r requirements.txt
python analyze.py
```

Результаты в `marketplace_report.csv` и `customer_retention.csv`.
