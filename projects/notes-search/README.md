# Notes Search

Локальный поиск по рабочим инструкциям, конспектам и личным заметкам на Java. Индекс хранится между запусками и обновляется при добавлении, изменении и удалении Markdown- и TXT-файлов. Поиск ранжирует совпадения по BM25 и показывает путь, номер строки и фрагмент текста.

Идею подсказали поисковые движки OpenSearch и Apache Solr из подборки GitHub Trending по Java. Этот проект применяет ранжированный поиск к локальной папке с заметками. [GitHub Trending](https://github.com/trending/java) · [OpenSearch](https://github.com/opensearch-project/OpenSearch) · [Apache Solr](https://github.com/apache/solr)

## Запуск

Требуется JDK 21 или новее. Из папки проекта выполните команды.

```bash
javac -encoding UTF-8 -d out NoteIndex.java NotesSearch.java
java -cp out NotesSearch examples "резервная копия"
```

Папка `examples` содержит три вымышленных текста, написанных для демонстрации. На первом запуске индекс построится по этим файлам. Первым результатом будет `backup-plan.md`, затем — `work/release-checklist.md`. Поиск требует присутствия всех слов запроса в документе. Регистр и различие между `е` и `ё` игнорируются. Словоформы сравниваются буквально. Необязательный аргумент после запроса задаёт лимит результатов, по умолчанию равный десяти.

Запустите ту же команду снова. Диагностика в стандартном потоке ошибок покажет `indexed=0 reused=3 removed=0`. Поменяйте строку в одной из заметок, добавьте файл и удалите другой. Следующий запуск переиспользует индекс неизменённых файлов, пересчитает новые и изменённые и исключит удалённые из результатов. С флагом `--rebuild` можно сверить выдачу с полной переиндексацией.

```bash
java -cp out NotesSearch --rebuild examples "резервная копия"
```

## Как устроен индекс

- Снимок в `.notes-search/index.tsv` хранит SHA-256 и частоты слов для каждого файла. Программа считывает байты всех файлов, чтобы заметить изменения даже при прежних размере и времени изменения, и заново разбирает текст только изменённых и новых файлов.
- Блокировка защищает обновление между процессами. Программа записывает снимок во временный файл и атомарно заменяет предыдущий. Если проверка текста завершится ошибкой, прежний снимок сохранится. При повреждении формата индекс строится заново.
- BM25 учитывает частоту слова, его редкость в коллекции и длину документа. Для фрагмента выбирается строка, в которой больше разных слов запроса. Если результат изменился между обновлением индекса и чтением фрагмента, утилита попросит повторить запрос. [BM25 в Apache Lucene](https://lucene.apache.org/core/10_3_1/core/org/apache/lucene/search/similarities/BM25Similarity.html)

Папка заметок должна быть доступна для записи индекса и находиться на файловой системе с поддержкой атомарного переименования. Документы читаются в UTF-8. При перенаправлении выдача также записывается в UTF-8. Словарь загружается в память, поэтому текущая реализация рассчитана на коллекции небольших и средних размеров.

## Проверки

```bash
javac -encoding UTF-8 -d out NoteIndex.java NotesSearch.java NotesSearchTest.java
java -cp out NotesSearchTest
```

Проверки запускают отдельные процессы Java и сравнивают выдачу полностью. Они проверяют повторный запуск, замену файла с прежними размером и временем изменения, добавление и удаление документов, пересборку повреждённого индекса и параллельные запросы.
